Two Mermaid JavaScript dependencies (`chunk-ZAUX2LTX-DB0mp1Yj.js` and `chunk-WQQL4CDK-CUv8jrmH.js`) failed with `net::ERR_CONNECTION_REFUSED` during the parallel module load. Other requests succeeded, and the diagram was already in its error state when the five-second assertion expired. This was a failed asset load, not simply an uncompleted render. The server inherited Python's pending-connection queue of five. The trace is consistent with [Winsock refusing connections when that queue fills](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-listen); reproducing that exact Windows behavior still requires the rebuilt native check.

Set the server's `request_queue_size` to `socket.SOMAXCONN`. A new regression opens 24 pending connections before the accept loop starts, then checks every response's status, JavaScript MIME type, and body. It failed with the old queue (connection timeout on Linux) and passes with the fix. No browser assertions, test timeouts, retries, renderer identities, or scroll-saving behavior were changed.
